# 灵活 OKR 树与打卡热力图设计

日期：2026-11-14  
状态：用户已确认方向，待审核完整设计稿  
范围：打卡页的树形目标管理、任务完成、进度汇总与打卡热力图

## 目标

- 目标结构由无限层级树决定，不依赖自然月或自然周。
- 用户可以创建、编辑、嵌套、拖拽、归档任意目标节点。
- 日期只作为可选的生效范围或任务计划，不决定 JSON 或 Markdown 的树形结构。
- 每日任务完成后，进度自动向上汇总。
- 打卡页顶部展示可筛选的完成情况热力图。
- 桌面端和移动端共用同一数据模型。

## 节点模型

每个节点拥有稳定 ID、标题、类型、排序和可选的日期范围。

```ts
interface OkrNode {
  id: string;
  parentId: string | null;
  title: string;
  kind: "direction" | "objective" | "key-result" | "stage" | "sprint" | "task";
  order: number;
  start?: string;
  end?: string;
  progressMode: "manual" | "children" | "count";
  target?: number;
  current?: number;
  schedule?: "daily" | "weekly" | "custom" | "one-off";
  archived: boolean;
}
```

规则：

- 树形层级由 `parentId` 决定，类型标签只用于语义和默认字段。
- 不强制“方向 → 年度 → 关键结果 → 阶段 → 冲刺 → 任务”的固定深度。
- 任意非归档节点都可以添加下级。
- `task` 是可直接打卡的叶子或子任务节点。
- `start`、`end` 可以为空；为空时表示长期有效。
- 日期范围可以跨月、跨周，也可以互相重叠。
- 修改日期只影响筛选、提醒和热力图应完成项，不搬动节点位置。

## 存储

目标树保存在 Vault 内可配置的 Markdown 文件中，默认：

```text
Goals/目标树.md
```

使用可读的 Markdown 嵌套列表：

```markdown
- 个人知识系统 #okr/direction ^okr-a1
  - 建立持续阅读习惯 #okr/objective ^okr-b2
    - 全年读完 50 本 #okr/key-result [progress:: count] [target:: 50] ^okr-c3
      - [ ] 读完《朝花夕拾》 #okr/task [schedule:: one-off] ^task-d4
```

规则：

- Markdown 是目标树的长期数据源。
- 缩进决定父子关系，块 ID 提供稳定身份。
- 内联字段保存进度模式和目标值。
- 插件另建可删除、可重建的索引用于查询和排序。
- 拖拽后调用 `Vault.process()` 原子改写目标树文件。
- 归档只改变节点状态，不删除历史任务和 Daily 完成记录。

## 每日完成事件

任务完成仍写入 Daily，而不是直接修改目标树中的完成值：

```markdown
- 21:30 #打卡 [task-id:: task-d4] [event:: completed]
  读完《朝花夕拾》并打卡。
  ^checkin-20261114-213000-a1b2
```

规则：

- 同一任务同一天只保留一个有效完成事件。
- 取消完成时记录取消事件或移除对应完成事件，由索引重新计算。
- 一次性任务在完成当天计入热力图。
- 重复任务在计划日期生成应完成项，在实际完成日期记录完成事件。
- 任务名称、父级或目标名称变化不破坏历史完成记录。

## 新增与编辑

### 新增

- 打卡页标题右侧提供“新建目标”。
- 每个节点提供“添加下级”。
- 新节点的默认类型由父节点决定，但用户可以在创建表单中修改。
- 创建表单字段：
  - 标题
  - 类型
  - 父节点
  - 可选开始、结束日期
  - 进度方式
- 创建成功后立即插入目标树，并展开父节点。

### 编辑

- 每个节点提供铅笔按钮。
- 点击后在该节点下方展开轻量编辑区，不跳到独立页面。
- 可修改标题、类型、日期、进度方式和目标值。
- 父级通过拖拽或编辑区修改。
- 修改后立即保存；保存失败时保留编辑状态并提示重试。

### 拖拽

- 每个节点提供独立拖动手柄。
- 桌面端使用鼠标拖放。
- 移动端长按后拖动。
- 拖到节点内部表示改变父级，拖到节点之间表示调整同级顺序。
- 禁止把节点拖入自己的后代节点，避免循环。
- 移动后节点 ID、历史完成记录和 Daily 引用保持不变。

### 归档

- 归档前显示受影响的下级数量。
- 归档父节点时默认同时归档全部下级。
- 历史完成记录和热力图历史保持不变。
- 支持从归档区恢复。

## 进度计算

节点支持三种进度方式：

1. `manual`：用户手动填写百分比。
2. `count`：按 `current / target` 计算，例如读书 `47 / 50`。
3. `children`：按直接下级进度合并计算。

默认规则：

- `task` 使用完成或未完成状态。
- 非任务节点默认使用 `children`。
- 没有下级且没有手动进度时显示“未设置进度”，而不是伪造百分比。
- 同级子节点默认等权；后续可以增加权重，但首版不引入。

示例：

```text
读完 50 本：47 / 50 = 94%
完成《朝花夕拾》：完成
阅读冲刺：2 / 3 个任务完成 = 67%
知识系统：下级进度平均值
```

## 打卡热力图

热力图位于打卡页顶部，默认展示最近 12 周。

### 统计单位

每天的有效完成率：

```text
当天已完成任务数 / 当天应完成任务数
```

规则：

- 当天没有应完成任务时显示为空，不显示为 0%。
- 一次性任务只在计划日期或实际完成日期产生应完成和完成数据。
- 重复任务按计划频率产生当天应完成项。
- 没有日期的长期任务只在完成时影响热力图。
- 选择某个目标后，只统计该目标子树中的任务。

### 强度

- 空白：没有应完成任务。
- 一级：完成率大于 0 且不超过 25%。
- 二级：大于 25% 且不超过 50%。
- 三级：大于 50% 且不超过 75%。
- 四级：大于 75% 且小于 100%。
- 完成：100%。

### 交互

- 默认范围为“全部目标”。
- 可切换到某个顶层目标或方向。
- 点击某天显示：
  - 应完成任务数
  - 已完成任务数
  - 未完成任务标题
  - “查看当天”入口
- 手机端使用底部卡片，桌面端使用轻量浮层。

### 摘要

热力图下方显示：

- 近 30 天完成率
- 当前连续完成天数
- 未完成任务数

不显示奖励、惩罚或红色警告，避免把记录变成压力来源。

## 页面布局

### 桌面端

- 左侧导航保持“日记、内容、打卡、搜索”。
- 打卡页顶部为标题、新建入口和热力图。
- 热力图下显示 OKR 树。
- 深层节点可折叠。
- 在宽屏下选中节点后可在右侧详情区编辑；窄屏使用行内展开。

### 移动端

- 从左侧抽屉进入打卡页。
- 热力图日期格保持紧凑尺寸；点击后打开日详情，并提供按周列表作为精确触控入口。
- OKR 树默认只展开当前目标路径。
- 新增和编辑使用底部表单。
- 拖动使用长按手柄，避免与页面滚动冲突。

## 错误与边界情况

- 循环父子关系：拒绝并提示原因。
- 目标树文件损坏：保留原文件，禁止覆盖，提供修复入口。
- 节点 ID 重复：阻止索引写入并标记冲突节点。
- 完成任务写入失败：不更新热力图和进度。
- 删除父节点：必须改为归档；如需永久清理，由单独的维护操作处理。
- 修改进度方式：提示是否保留已有手动值。
- 目标树文件被外部编辑：重新解析并更新索引。

## 非目标

- 强制目标必须归属于年、月、周。
- 固定层级数量。
- 自动替用户创建 OKR。
- 用热力图制造连续打卡惩罚。
- 删除历史 Daily 完成事件。

## 验收标准

- 用户能新建任意层级节点，并添加、编辑、拖拽和归档下级。
- 树形结构不依赖自然月或自然周。
- 日期范围可选且支持跨月、跨周。
- 任务完成后各级进度自动重算。
- 同一任务不会被重复计数。
- 热力图能区分未安排、部分完成和全部完成。
- PC 与移动端使用同一套目标树和完成记录。
- 目标树和 Daily 均为可读 Markdown，索引可完整重建。
