# Daily 为中心的日记、目标与书籍记录设计

日期：2026-11-12  
状态：待用户审核  
范围：统一输入、动作标签、年度目标进度、书籍聚合视图和长文转换

## 核心原则

- 所有内容从同一个 Diary 输入框开始。
- Daily 是普通记录、任务完成和书籍阅读事件的唯一正文来源。
- 一本书不再对应一篇固定主文件。
- 同一本书跨多天产生的记录，通过稳定 `book-id` 聚合成一个虚拟书籍视图。
- 只有真正的长文才创建独立 Markdown 文档。
- 标签负责展示和搜索；稳定 ID 负责数据关系与进度计算。
- 保存优先，分类其次。用户可以先写完，再接受标签和目标建议。

## 两类标签

### 普通标签

普通标签只用于分类和搜索，不改变保存流程：

```text
#此刻的心情
#对明天说句话
#最想记录的瞬间
#启发
#摘要
```

### 动作标签

动作标签会触发一个轻量的后续面板，但不会阻止正文先保存。

首版保留以下动作：

| 标签 | 触发内容 |
|---|---|
| `#book` | 书名、作者、阅读状态、评分、所属关键结果、是否计入读书数量 |
| `#长文` | 长文标题、创建独立长文文档、将正文迁入长文并保留 Daily 入口 |
| `#打卡` | 选择今日任务、完成任务、确认一次性或重复任务 |

规则：

- 点击动作标签后，在输入框下方展开对应面板。
- 用户也可以直接在正文中输入动作标签，保存后出现相同建议。
- 未使用动作标签时，正文保存为普通 Diary 记录，并建议 `#待整理`。
- 普通标签可以自动建议；涉及目标进度、完成任务和创建长文的操作必须由用户确认。
- 动作标签在 Markdown 中仍然是普通标签，行为由插件的动作注册表决定。

## Diary 记录模型

每次输入生成一个带稳定块 ID 的 Daily 条目：

```markdown
- 21:30 #book #读后感
  读完《朝花夕拾》，印象最深的是……

  %% journal-meta: {"entryId":"entry-20261112-213000-a1b2","kind":"book","bookId":"book-chaohua-xishi","event":"completed","keyResultId":"kr-reading-50","taskId":"read-chaohua-xishi-2026","rating":4} %%
  ^entry-20261112-213000-a1b2
```

说明：

- 正文保留在 Daily，不在其他位置复制。
- `journal-meta` 是插件维护的隐藏元数据，阅读界面不展示。
- `entryId` 与块 ID 全局唯一。
- `kind` 可取 `note`、`book`、`task`、`longform-ref`。
- `bookId` 标识同一本书，不受书名修改影响。
- `keyResultId` 和 `taskId` 使用稳定 ID，不使用显示名称。
- 普通标签直接写入正文；结构化字段只保存一次。

## 统一输入流程

1. 用户输入文字、标题或图片。
2. 用户可以直接点击 `#book`、`#长文`、`#打卡`，展开相应补充面板。
3. 用户也可以直接保存；保存后系统给出动作和标签建议。
4. 用户确认建议后，更新当前 Daily 条目的隐藏元数据，或执行长文转换。
5. 分类失败时，内容仍保存为 `#待整理` 的普通 Diary 记录。

### `#book` 面板

- 搜索并选择已有书籍，或新建一本书。
- 可选填写作者、评分和阅读状态。
- 选择是否计入某个关键结果。
- “读完”必须明确选择；只写书评不会自动增加读书数量。
- 保存后生成一条 `kind: book` 的 Diary 事件。

### `#长文` 面板

- 输入长文标题。
- 将当前正文迁入独立 Markdown 文档。
- 当前 Daily 条目改为摘要与长文链接。
- 长文文档保留 `source-entry-id` 和 `journal-day`，避免重复归属。

### `#打卡` 面板

- 选择当前任务。
- 标记完成或取消完成。
- 一次性任务完成后可关联书籍、长文或其他 Daily 记录。
- 重复任务只记录当天完成事件。

## 书籍聚合视图

同一 `bookId` 的所有 Diary 条目组成一个虚拟书籍页面，不创建正文文件。

视图包含：

- 书名、作者、最近状态、评分。
- 是否已读完、完成日期、所属关键结果。
- 全部阅读记录，按 Daily 的日期和时间正序排列。
- 每条记录返回对应 Daily 块。
- 可追加一条新记录；新记录仍写入今天的 Daily，而不是聚合页。

示例时间线：

```text
2026-11-12 21:30  读完并打卡
2026-11-15 10:20  补充了一条关于人物命运的启发
2026-11-20 08:40  修改评分并补充书评
```

## 目标进度

“读完 50 本”的有效数量为：同一关键结果下，具有不同 `bookId` 且存在已确认 `event: completed` Diary 事件的数量。

补充规则：

- 同一本书在同一关键结果中只计一次。
- 后续书评、摘录和补充不增加数量。
- 删除或撤回完成事件后重新计算。
- 修改书名、作者、标签或 Daily 展示文案不影响进度。
- 插件索引只是派生缓存，可从 Daily 重建，不作为计算真源。

## 长文规则

- 短内容始终留在 Daily。
- 用户选择 `#长文` 后，Daily 只保留标题、摘要、附件和长文链接。
- 长文文档本身使用标准 Obsidian Markdown，可在原生编辑器中打开。
- 长文中的修改不重复生成目标进度。
- 长文可以关联 `bookId`、`keyResultId` 和原始 `entryId`。

## 界面行为

- Diary 输入框上方或下方保留可横向滑动的标签条。
- 普通标签显示为低强调胶囊。
- 动作标签带图标和轻微强调，但仍保持一行。
- 选中动作标签后，在输入框下方展开对应面板，不跳出当前页面。
- Daily 时间线中的 `#book` 卡片点击后打开该书聚合视图。
- 长文卡片点击后在 Obsidian 原生编辑器中打开长文。

## 从 Daily 生成与重建

- 插件只扫描配置的 Daily 文件夹，不遍历整个库来渲染每次界面。
- 启动时建立当前年度事件的派生索引。
- 监听 Daily 文件创建、修改、重命名和删除，增量更新索引。
- 索引损坏或版本升级时，可以从 Daily Markdown 完整重建。
- Markdown 删除后，相关长文不自动删除，但不再参与目标统计。

## 错误与边界情况

- 缺失或损坏的 `journal-meta`：按普通 Diary 记录展示，不参与目标计算。
- 找不到 `keyResultId`：保留记录并标记为“目标待修复”。
- 找不到 `bookId`：保留记录并显示“书籍待关联”。
- 重复完成事件：同一 `bookId + keyResultId` 只计一次。
- 长文创建失败：原 Daily 正文保持不变。
- Daily 写入失败：不执行后续索引和完成事件更新。
- 同一分钟输入多条记录：`entryId` 使用秒与随机后缀保证唯一。

## 非目标

- 为每本书创建固定主文件。
- 自动抓取网络书籍元数据。
- 自动完成目标或自动计入读书数量。
- 将标签本身作为唯一数据关系。
- 在没有用户确认时创建长文。

## 验收标准

- 所有普通记录都能从 Daily 输入框完成，不要求提前选择笔记类型。
- 选择动作标签后会展开对应面板，而不是跳转页面。
- 点击 `#book` 可以查看同一本书跨日期的完整聚合时间线。
- 一本书对同一关键结果只贡献一次完成进度。
- 后续书评只增加时间线，不重复推进读书数量。
- `#长文` 会创建独立 Markdown，并在 Daily 保留可返回的入口。
- 删除或损坏派生索引后，可以从 Daily 重建书籍与目标数据。
